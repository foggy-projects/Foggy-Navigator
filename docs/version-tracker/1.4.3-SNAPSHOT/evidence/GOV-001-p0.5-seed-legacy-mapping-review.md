# GOV-001 P0.5 Seed / Legacy Mapping Review

## Conclusion

P0.5 的 seed/legacy 静态映射门槛已关闭，可以授权不改变现有 allow/deny 的 P1A foundation/shadow 实现。当前源码中不存在可被安全自动提升为 `INSTANCE_ROOT` 或 `SAAS_PLATFORM` 的 legacy record；P1A 不得创建 S1/S2 principal、platform grant、tenant authority、management credential 或 management token 业务数据。

唯一合法的 upstream-admin canonical adapter 映射为：

```text
principalType = UPSTREAM_SYSTEM_ADMIN
credentialLane = LEGACY_UPSTREAM_ADMIN
```

`CLIENT_APP_ADMIN_ALL`、tenant alias、namespace、旧 scope alias、legacy runtime-key compatibility bridge、名称包含 `foggy-world-sim` / `tms-x3`，均不能把它提升为 `INSTANCE_ROOT`、`SAAS_PLATFORM`、provisioning/security lane 或 production authority。

本结论来自当前源码、实体、配置和迁移机制的静态复核。未查询实际数据库行，未读取账号、claim token、credential secret、`upstreamUserToken` 或本机 profile。实际脱敏数据盘点是 P1B seed/签发前置，不阻塞纯 additive、legacy-adapter、shadow-only 的 P1A。

## Review Boundary

- reviewed: tracked entity/schema fields、credential issuance/resolution logic、scope compatibility、ClientApp provisioning、task token v2、resource ownership signals、startup initialization、JPA profile 和 migration pattern。
- not reviewed: 实际数据库内容、本机 `.env`/`.navigator` profile、真实 SIM/TMS credential、运行态调用、external/production readiness。
- closed gate: P0.5 是否存在安全的自动 seed/migration 路径，以及 legacy record 如何进入 canonical shadow context。
- deferred gate: P1B 前对目标环境执行只含 ID/fingerprint/status/conflict 的数据库 inventory，并由 Owner/operator 对每条 typed principal/grant/tenant authority seed 显式批准。

## Current Compatibility Facts That Must Not Become Authority

1. Upstream admin 存在 `CLIENT_APP_ADMIN_ALL`，并会 canonicalize 多个旧 scope alias。
2. Upstream admin tenant 校验支持由 `nav_<upstream>_<sourceTenant>` 推导 source tenant alias。
3. 旧 `CLIENT_APP_MANAGE` 可通过 compatibility bridge 签发其已可管理 ClientApp 的 runtime key。
4. Upstream-admin 默认 scope 涵盖 ClientApp、Worker、WorkerPool、Directory、Model、Agent 和 binding/grant 管理。
5. ClientApp control 空 scopes 会回退当前 16 项默认 control scope，且 `CONTROL_PLANE_ALL` 可匹配任一 control scope。
6. 新建或显式 rotate 的 upstream tenant ClientApp provisioning 会同时签发 runtime long-term credential 与 control credential；默认 control credential 使用完整默认 control scopes，且两类 long-term credential 都可在未指定时无到期。
7. Upstream-admin 默认 24 小时；审批时 `claimTtlMinutes=0|-1` 可显式签发无到期 admin key。

以上事实只能用于兼容回归和 shadow diff，不能成为 S1/S2 typed principal、authority ceiling、security lane、tenant ownership 或 production readiness 的授权依据。

## Deployment Identity Rule for P1A

当前非文档源码中没有 `navigatorInstanceId` 或 `environmentProfile` 的权威实现。P1A 必须新增服务端拥有的 deployment identity provider：

1. request body、header、CLI profile、URL 或 legacy tenant/upstream 字段不得覆盖服务端 instance/environment。
2. local/internal-dev 保持可启动兼容；允许明确标记为 dev-only 的稳定 fallback，但其结果必须 `productionUsable=false` 并产生可见告警。
3. production profile 必须显式配置非占位 instance identity 和 environment profile；缺失、未知或冲突时启动失败。
4. legacy adapter 可把“当前部署 identity”加入 shadow context，但必须标记来源为 deployment-inferred/legacy-adapter；不能反向宣称 legacy record 原生绑定该实例，也不能用它自动 seed typed record。
5. P1A 不改变跨实例 enforcement；canonical shadow 对缺失 instance binding 的 legacy authority 应记录不确定或拒绝差异，供 P1B mapping 决策。

## P1B Pre-Seed Inventory Contract

在创建任何 `INSTANCE_ROOT`、`SAAS_PLATFORM`、platform grant、tenant authority 或 typed credential 前，必须对目标 Navigator 实例执行一次脱敏 inventory。输出只能包含：

- source table/type、record ID、credential fingerprint/prefix-suffix、status、expiry state、revocation state；
- upstreamSystemId、tenant/clientApp/resource ID 或其不可逆摘要、namespace、owner-present/conflict flags；
- proposed canonical principal/lane、disposition、quarantine reason、approval reference；
- count/hash/checksum 和执行环境的 `navigatorInstanceId + environmentProfile`，不含任何 secret/token/account material。

不得读取、输出或保存：credential 明文、secret hash 全值、claim token、账号密码、完整请求体、`upstreamUserToken`、LLM key、本机 env/profile 内容。

### Mandatory quarantine

以下任一情况必须保持未迁移并 fail closed，不能补猜或自动降级：

1. 缺 instance/environment，或 legacy 来源与目标部署不一致；
2. owner、tenant、upstreamSystemId、ClientApp 或 namespace 相互冲突；
3. orphan reference、重复/歧义 mapping 或多个 ClientApp 对同一 tenant/upstream 给出不一致事实；
4. expired、revoked、inactive 或状态未知；
5. 无到期 legacy credential；
6. 仅凭宽 scope、旧 alias、tenant list、名称或调用历史推导高权限；
7. 无权威 tenant ownership 或缺 Owner/operator 具名审批。

### Explicit P1B seed rules

- S1 `INSTANCE_ROOT`：由 operator-approved instance subject mapping 新建 typed principal，再独立签发 control/security credential；不从 upstream-admin 或 ClientApp credential 转换 secret。
- S2 `SAAS_PLATFORM`：由 operator-approved exact instance + upstream mapping 新建 typed principal/platform grant；legacy upstream-admin 最多作为候选核验输入，必须重新签发 `SAAS_PROVISIONING`，`SAAS_SECURITY_ADMIN` 永远独立签发。
- tenant authority：只能来自权威 owner mapping 与显式审批；ClientApp 数量、tenant alias 或 legacy authorized tenant list 不能直接生成 ownership。
- secret handling：typed credential secret 只显示一次并只存 verifier/ref；任何 legacy secret 不复制、不回显、不复用。

## Rollback and No-Downgrade Rules

1. P1A 正常回滚按 route family 关闭 shadow/evaluator 或回到 legacy enforcement，保留 additive schema 和 append-only decision evidence；不得把 drop table 当常规回滚。
2. 必须提供结构性 forward/rollback SQL 和测试，但 rollback SQL 只能在受控、确认无需要保留数据的环境执行。
3. rollback 不得恢复、补发、复制或自动降级高权限 credential，也不得把 typed principal 转回 upstream-admin/control/runtime credential。
4. P1A 未签发 typed credential，因此回滚不应产生任何 credential lifecycle 副作用。
