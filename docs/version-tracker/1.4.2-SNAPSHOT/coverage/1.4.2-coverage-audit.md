- 已有迁移/清理证据：task capability、Worker credential、terminal state、Claude tenant 的 H2/JPA 与一次性 MySQL 8.0/8.4 forward/rollback；Monitoring、metadata-query、code-review、Echo、旧 Provider 契约按独立提交和静态扫描收口。
- 已有回归保护：BUG-001、BUG-002 均有定向自动化；BUG-001 所在 launcher 依赖链有后续 hosted 复验，BUG-002 由本机 Open SDK 定向 142 tests 与当时根 reactor 17/17 clean test 支撑，最新 hosted Java lane未覆盖 Open SDK；旧 Provider 路由和 deprecated Provider SPI/DTO 有精准归零扫描。
- 已有体验证据：loopback + 一次性 H2 下同 tenant 双用户真实注册/登录，Session owner 访问与非 owner 列表隐藏、history/SSE/direct read 拒绝。
- 证据不足的共同特征：真实 external/non-loopback、Provider Task、共享数据库、审批恢复取消 UI、管理员/system 通路及完整内部文件/终端/Worker 主链未运行。

## Gaps

1. AC-02 至 AC-06 均为 critical，当前主要由 unit/JPA/contract 支撑；缺少 ClientApp 双主体、真实 Lang/Codex Biz Task、审批/恢复/取消、跨 task/函数、credential 缺失与撤销后的网络级负向矩阵。
2. P2 的 Codex credential 安全转发、external execution policy、workspace/tool/sandbox/approval/egress 上限、pause/generation 和 reliable audit/outbox 尚未实现；这些缺口需要先回到实现，不能只补测试文档。
3. AC-01/AC-03 的 Task ownership live fixture、共享数据库、全列表 tenant、Provider taskId、显式 admin/system 和完整可信内网工作台主链缺失；现有 Session live 不能外推到 Task/Worker。
4. AC-10 的 P4 低风险候选仍为 `not-started`，没有逐项引用扫描、删除提交、验证和回滚证据；不应以 P5/P6 已完成切片替代。
5. AC-11 的代码切片已有较强静态/clean/hosted 证据，但 Monitoring/metadata-query/Echo 的专项启动或页面/脚本体验仍不完整，未知共享资源被明确保持 `not-run`。
6. AC-12 的当前主文档已对齐，但失效 Skills 和早期设计文档的 current/historical/candidate 分类尚未完成 Owner 复核。
7. repository CI 已成功运行，但 main 当前未配置 required checks/branch protection，修复后的 nightly 也未实跑；这不影响已登记的 clean baseline 事实，却影响版本治理门禁闭环。
8. 复杂 external 与 Task E2E 尚无独立测试用例文档；补测试前应先冻结账号、tenant、ClientApp、Worker、token、审批状态和拒绝码矩阵。
