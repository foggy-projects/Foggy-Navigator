## Coverage and Limits

- The E2E uses isolated H2, a repo-local app-server Worker, the pinned repo-local Codex CLI and mock Responses API.
- A JVM object-identity marker prevents HTTP JSON or metadata from opting into first-affinity initialization.
- The Codex service locks and verifies a same-user, same-tenant, Provider-compatible pristine Session before selecting a new app-server runtime.
- Ordinary app-server continuation without persisted affinity remains fail closed; existing Session and legacy SDK behavior is exercised by the affected module suite.
- Remote deployment/retest, source-message persistence races, generic HTTP error mapping and `EXISTING_SESSION` behavior changes are outside this delivery.
